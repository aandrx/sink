# 0.2.17 verification evidence

Patch release for the remaining IndexedDB connection-closing error observed on 0.2.16.

## Root cause

PouchDB caches one IndexedDB connection per database name. Sink's engine shutdown still closed that shared connection. If a replacement plugin instance had already opened the same database, the close interrupted its transactions.

The previous 0.2.16 generation guard only prevented an older instance from closing when a newer instance already existed. A newer instance could still open during the close itself, leaving the race.

## Fix

`SyncEngine.shutdown()` no longer calls `LocalDB.close()`. It still:

1. Cancels timers, reviews, hearts, and replication.
2. Waits for an in-progress startup to settle.
3. Drains the operation queue.

The shared PouchDB connection remains cached for the replacement plugin instance. An explicit local-database rebuild still calls `destroy()`.
