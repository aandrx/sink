Passing scenarios:

3. Secondary publication: nothing published before authorization; a subsequent upload does not ask again in that session.

7. Encrypted text above 64 KiB: encrypted parent/chunks, no fixture plaintext marker in CouchDB, matching vault hashes.
8. Built-in inbound selector: legacy snapshot is not downloaded into the local database; allowed file/chunk/device/tombstone documents and live updates propagate.
9. Real retained CouchDB conflict revisions: visible revision selector, explicit non-winning server choice, all remote conflict leaves retired, no `_conflicts`, local and remote winner changed as expected.

Roles, file edits, and sync triggers use real plugin/Obsidian APIs; review/authorization choices use real DOM controls. Continuous replication is paused/resumed through the real engine API where fixtures need deterministic operation boundaries. These are not mocked runtimes, but they are not an all-keyboard user journey or two physical devices.

## Review-driven repairs

- Fixed forced-connected status and disagreement among indicators; both replication directions remain live.
- Propagated upload failure instead of counting it as applied.
- Persisted skipped/deferred review markers and preserved arrivals during cancellation. Held IDs are revision-scoped so a new remote revision is not suppressed for the session.
- Replaced fake merges with explicit side choices; SHA-256 fingerprints distinguish known fast-forwards from divergence.
- Metadata-only operation candidates and one-body-at-a-time preparation avoid retaining vault-wide plaintext.
- Grouped backup preflight respects the snapshot budget while preserving one review. Every backup completes before any selected file is changed; a later backup failure applies none.
- New snapshots are local-only, encrypted when configured, with bounded index retries and caught settings error paths.
- Repaired footer clipping, pager overlap, dialog labeling, empty Apply state, preview races, and reduced-motion/paused-state styling.
- Retained conflict reviews now expose every retained server revision, support a non-winning selection, require explicit resolution, and abort if an unreviewed live revision arrives during retirement.
- Startup performs one successful pull before continuous replication, treats remote-only files as server additions rather than inferred local deletions, reconciles offline local edits/new files/deletions/divergence through one review, pins writes to reviewed revisions, and does not seed an empty database. Retry recovery is queued after a failed startup pull.
- UI review surface follows Local/Remote terminology, has no explanation legend, starts with the diff collapsed, and opens a diff by clicking anywhere in the file box (excluding its controls).

## Remaining verification limits

- The user's actual live disconnect was not diagnosed: saved connection credentials and production note/database contents were never accessed. The general status, startup, and convergence defects found in this branch are repaired and covered by synthetic tests, but the specific live configuration still needs a disposable-vault check.
- The grey-screen cause remains unconfirmed. No long-duration memory/renderer soak, cross-machine Windows/macOS/Tailscale matrix, mobile/background testing, or real network-fault matrix was completed.
- Raw allowed file documents can still be oversized; application limits are not streaming or a hard memory cap.
- Previously replicated plaintext snapshots, historical revisions, and backups are not retroactively secured. Remediation requires separate approval.
- New snapshot summaries index the most recent 50 snapshots. Older payloads are retained, not deleted, but are not discoverable through that recent index.
- Two isolated local processes do not prove behavior on two physical devices, touch input, or every Obsidian theme.
