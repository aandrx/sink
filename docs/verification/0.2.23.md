# 0.2.23 verification evidence

Mobile review UI release. Desktop review behavior and sync algorithms are unchanged from 0.2.22.

## Automated checks

- `npm test`: **168 passed, zero failures/skips**.
- `npm run typecheck`: passed.
- `npm run build`: passed.
- Full isolated Electron/CouchDB E2E: **11 passed, zero failed**.
- Evidence: `/tmp/sink-e2e-artifacts/2026-11-09T15-24-17-457Z-09cdd4/evidence.json`

The desktop E2E covers review paging, cancel/confirm, secondary-device permission, divergent edits, reconnect/catch-up, startup reconciliation, encrypted chunk transfer, unchanged attachment restarts, snapshot display, inbound filtering, and retained conflict resolution.

## Mobile review checks

- `src/ui/BatchReviewModal.ts` selects the mobile workspace with `Platform.isMobile`; desktop keeps the existing side-by-side workspace.
- DOM tests cover:
  - iOS cards and segmented decisions instead of desktop selects and checkboxes.
  - Effective counts and emitted decisions after per-file choices.
  - Detail navigation, unified diff, decision sync, and list `inert` handling.
  - Bulk actions across all files, including blocked rows.
  - Retained-conflict revision selection and emitted `conflictRevision`.
  - Pager behavior across more than one page.
- `src/ui/DiffView.ts` adds `renderUnifiedDiff`; tests verify deletes and inserts render in one column.
- Visual rendering used the real `BatchReviewModal` component and repository `styles.css` in Firefox at a 390 × 844 viewport, in light and dark themes. Screenshots are stored with the release notes:

## Behavior preserved

- Local, Remote, and Skip decisions are unchanged.
- Deletions still use the destructive confirmation.
- Apply and Cancel still resolve the complete review.
- Blocked rows remain unselectable and are reported in the count.
- Conflict revisions still require an explicit chosen leaf.
- Desktop E2E passed without changes to its review expectations.

## Limits

- The mobile layout was not exercised on a physical iPhone/iPad or inside the Obsidian iOS app. The 390 × 844 renderer check validates layout and component state, not WKWebView safe-area behavior or touch gestures.
- The mobile workspace applies to all Obsidian mobile platforms. Desktop and Settings/Setup layouts are unchanged.
- No mobile-specific E2E harness exists; mobile coverage is DOM tests plus the rendered component check.
- The grey-screen, historical plaintext, and cross-version limits documented in [STABILITY.md](../STABILITY.md) remain unchanged.
