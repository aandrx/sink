# Sink 0.2.15: safer sync and complete reviews

Development branch, not a published release. The release tag must be `0.2.15`, without a `v` prefix.

## Scope

- One review workspace per explicit pull, with bounded discovery and application, lazy side-by-side previews, and selections preserved across pages.
- Cancel ends the operation. Secondary publication permission is checked before applying changes that require an upload.
- Explicit Local/Remote choices for divergent edits and retained conflict revisions. The old patch-based replacement is not a true three-way merge and must not silently discard local changes.
- Retained CouchDB conflict revisions can be reviewed, including a non-winning server revision. Applying a choice publishes it as the winner and retires only the reviewed losing revisions. If an unreviewed live revision arrives during retirement, cleanup stops and the conflict remains pending.
- Startup reconciles local edits, new files, deletions, remote fast-forwards, and divergence after Sink was stopped. An empty database is not seeded automatically. Startup writes are pinned to reviewed revisions and one operational review is used.
- Session permission never bypasses deletion/conflict decisions.
- New snapshots are local-only and encrypted when vault encryption is enabled. Previously replicated plaintext snapshots and historical revisions need separately approved remediation.
- Connection state must not be forced to connected by plugin startup or one replication direction masking another.
- The review UI uses Local/Remote terminology, has no explanation legend, and starts with the diff collapsed. Clicking anywhere in a file box, or focusing its name and pressing Enter, opens the diff.

## Compatibility and safety

Use the same build on all test devices. Do not upgrade a production database with old clients still running. Existing version gates are application policy, not server-side access control.

The grey-screen cause remains unconfirmed. Keep Sink disabled in the live vault until disposable-vault testing passes. Back up the vault, including configuration, and CouchDB first. Install all three assets together: `main.js`, `manifest.json`, and `styles.css`.

Inbound replication uses CouchDB's built-in selector to exclude legacy snapshots and unsupported document families before downloading their bodies. This requires CouchDB 3 as documented. File limits are application safeguards, not streaming or a hard memory cap on allowed raw replication. Snapshots are bounded, not automatically pruned. A logical pull is not an atomic filesystem/database transaction; interruption can leave a partially applied operation.

Conflict resolution intentionally retires the remote revisions that were shown and not chosen. A local safety snapshot is taken before the operation, but it contains local files only; it is not a backup of every losing remote revision. Do not resolve a conflict unless the chosen revision is the one intended.

## Verification

- `npm test`: 132 focused class and DOM regressions pass.
- `npm run typecheck` and `npm run build`: pass.
- `npm run test:e2e`: isolated real Obsidian/Electron instances, IndexedDB, and temporary CouchDB. The complete suite passed 9/9, including startup offline changes and real CouchDB conflict resolution.
- Docker, Obsidian, and a graphical display are required. E2E never targets a live vault or production database.

Actual results and limitations are recorded in `docs/verification/0.2.15.md`. Passing automated checks is not proof that a grey-screen crash cannot occur. Cross-machine/OS testing, long-duration soak testing, mobile behavior, historical plaintext exposure, and real network failures remain distinct rollout gates. The specific live disconnection still needs verification against the user's configuration.
