# Sink 0.2.18: bounded device history

Patch release for the manual-sync/status failure caused by oversized local device metadata. Tag: `0.2.18`, without a `v` prefix.

## Root cause

The local PouchDB device records were updated every heartbeat. Without compaction or a revision bound, one device document grew to an unreadable IndexedDB value:

`UnknownError: Failed to read large IndexedDB value`

Reading it made PouchDB mark the database globally failed, close the connection, and report:

`Failed to execute 'transaction' on 'IDBDatabase': The database connection is closing.`

The local database contains one device record with 3,802 revisions and another unreadable record. The remote CouchDB and live replication were not the cause.

## Fix

- Local PouchDB now uses `auto_compaction: true` and `revs_limit: 100`.
- Device heartbeat records can no longer accumulate unbounded revisions on new or rebuilt local databases.
- The plugin no longer closes the shared IndexedDB connection during engine shutdown, preserving the replacement instance's connection.

## Required one-time action

The fix cannot repair an already-unreadable IndexedDB record in place.

1. Back up the vault and CouchDB.
2. Install 0.2.18 on the device.
3. Open **Settings → Sink → Rebuild local database**.
4. Let the initial pull rebuild the local cache.
5. Confirm notes are intact before enabling config-folder sync.

The rebuild destroys the local cache only. Vault files and the CouchDB database are not deleted. Do not rebuild without a backup if the vault has local-only changes that have not reached the server.
